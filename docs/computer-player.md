# 电脑玩家

当前固定地图（资源 `1028`）在人机对战中自动创建一个近战电脑玩家，不增加启动器开关。需要重新进入一局；旧对局热更新不会补建电脑实体。

## 行为与范围

- 玩家为 `actor/rid=1`，电脑为 `2`，阵营始终与所选玩家阵营相反。电脑使用已有步兵模型、武器 `1030411` 和原动作状态链。
- `PREPARE`、`START` 不执行 AI。进入 `GAME` 且真实双实体位姿与导航数据就绪后，电脑追击玩家；进入可达的 2 米近战范围后停止、转向。普通进攻等待 300 ms，威胁格挡与收招反击优先于普通进攻。
- 基础步速与玩家一致：以 3 米／秒慢跑起步，连续前进 2 秒后以 5 米／秒快跑，位移、速度字段和移动动画同步切换。停止、攻防、受击及大角度转身后重新计时。
- 使用简单行为树选择格挡、反击和普通攻击；四向攻击按位置、已观察到的防守、最近招式和可重放随机扰动评分，不固定轮换。移动、动作、序号和定时器与玩家独立，不发送玩家位置修正。
- 寻路失败、目标离开网格、快照超过 250 ms 或实例不匹配时停止决策与移动。不跨墙直追，不根据一次按键报告持续外推玩家位置。
- 支持双向基础命中、受击和掉血；初始血量 100，普通攻击扣 20，玩家冲刺攻击扣 40，最低为 0。零血量仍保留动作与受击，不自动回血，也不触发死亡、复活、比分或胜负结算。
- 暂不包含多电脑、骑兵和精确刀刃碰撞。

## 复用与本地实现

| 来源 | 当前用途 |
| --- | --- |
| `vfs/map.vfs` 内 `data/scene/map/lysd/anavmesh.dat` | 只读提取原 Havok `hkaiNavMesh` 的面、边、顶点与邻接关系。 |
| 客户端实体查询与 `GeMovable` 位置、朝向 getter | 在原游戏帧线程中采样双方坐标和朝向，保留控制器高度偏移，朝向弧度转为角度。 |
| 原场景 `acollision`、Havok 射线查询与形状材质 | 查询实际静态场景的命中点、法线与材质，不用导航绕行代替武器遮挡。 |
| 原 MOVE 接收、角色控制器和模型状态链 | 执行电脑的位置、朝向、移动、攻防与受击动作；继续使用游戏的重力、碰撞和动画。 |
| `py_trees 2.6.0` | 编排近战决策的优先级，不替代动作、命中或导航。 |
| 本地业务规则 | 目标选择、追击、反应时间、攻击选招、招架选择、近战判定和血量。 |
| 本地寻路 | 面图 A*、收窄门户、funnel 收紧与逐面高度插值；收紧结果有歧义时使用同一连通走廊的门户中点。 |

编辑器的 AI 节点声明不是可执行客户端 AI 的证据；方向适配组件也不等于完整的电脑决策。当前没有直接调用尚未闭合参数、所有权和生命周期的原生 Havok 寻路入口，不将本地规则称为原服 AI 的还原。

### 战斗决策

[bot_decision.py](../src/Business/scripts/bot_decision.py)在原有 100 ms 决策节拍中执行 `py_trees` 优先级选择器，不增加线程、阻塞等待或武器轨迹采样。决策顺序为：

1. **完成当前动作**：受击、格挡反馈、地形反弹或已开始的攻防动作期间，不另选招或强行取消动作。
2. **威胁格挡**：玩家正在准备、蓄力或出招，且双方实际位置、朝向、近战范围与地形查询允许接触时，观察至少 150 ms 后选择格挡。左右仍偏好镜像动作，但实际格挡判定不限左右配对；冲刺选下格挡。玩家背对电脑挥刀、距离过远或隔墙，不触发此分支。出招剩余时间不足以覆盖 200 ms 格挡准备和 100 ms 命中窗口尾部时，等待这一刀结束，不再起一个过晚的格挡。格挡发起 600 ms 后自动松开。
3. **收招反击**：电脑空闲、玩家正在收招或播放被格挡／地形反弹，观察该阶段至少 150 ms、阶段剩余至少 100 ms，且电脑具备有效攻击接触条件时，优先起手。反击仍使用原武器准备、出招和收招时长，是择机进攻，不保证在对手恢复前命中。
4. **普通进攻**：转向后的 300 ms 等待结束且接触条件有效时，给四向攻击评分。已观察到的上／下格挡降低同向攻击评分，左／右格挡同时降低两种横向攻击评分；最近一次攻击降低重复评分，距离、相对角度、高差与有限随机扰动提供偏好。评分不改变各方向的命中范围和伤害。

150 ms 观察时间按 100 ms 决策节拍检查，不是逐帧精确反应。攻击正常推进到下一阶段保留最初观察时间，新的挥击或方向变化重新计时。只有实际选招时才推进随机序列；等待和热更新不消耗序列。世界快照失效时丢弃观察记录。

树节点只在单次决策期间存在；观察记录、最近招式和随机序列状态保存为可序列化会话数据，热更新后保留，不跨对局共享黑板。依赖及原始许可证随产品离线分发，见 [vendor/README.md](../src/Business/vendor/README.md)；依赖升级需重启启动器，策略脚本继续支持热更新。暂不包含后撤、侧移、佯攻、复杂连招或学习型策略。

### 导航资源配置

仅支持当前客户端基线中的单个网格：归档偏移 `203763021`，压缩长度 `89863`，解压长度 `156048`，解压数据 SHA-256 为 `b92da3edc697ada355a95359d94ff3025841bf2de57833297901361452c539a3`。资源有 1803 个面、8069 条边和 4100 个顶点。

[资源读取器](../src/Business/scripts/navmesh_resource.py)支持该资源的 Havok v5 tagfile：带符号变长整数、字符串引用、继承字段掩码和结构数组的列式编码。逐段 zlib 必须完整结束，长度、摘要和根类型必须匹配；不将客户端资源或解析缓存写入项目或产品包。

Runtime 的 `clientDirectory` 是客户端可执行文件目录 `Bin`，因此资源路径为 `clientDirectory/../vfs/map.vfs`，不是 `Bin/vfs/map.vfs`。

[步行寻路](../src/Business/scripts/navigation.py)排除退化和非凸 XY 面、过窄门户、非互反邻接及不支持的接缝。门户宽度按 0.35 米代理半径检查；相邻面的高度差限于 0.4 米。这是当前步行配置，不代表完整复现 Havok 的避障与角色碰撞算法。

### 基础近战

[combat.py](../src/Business/scripts/combat.py)只在攻击出招阶段判定命中：出招 120 ms 后开始，每 50 ms 检查一次，收招前 100 ms 关闭。每次挥击最多命中一个目标一次，准备、蓄力和收招不造成伤害。双方位置和朝向必须来自当前实例且不超过 250 ms 的同帧快照；不使用可能滞后的按键朝向或电脑计划朝向判定命中、招架。

命中范围为水平距离 2.2 米、高度差 1 米、正面左右各 60°。朝向缺失或非有限时不假定为 0°。导航连通性、台阶和绕行不再直接否决攻击；实际场景碰撞决定遮挡。

地形查询在同一帧读取已加载的 `acollision` 刚体及其所属战斗世界，调用原生射线入口，收集器只接受该场景刚体，不把角色判为墙。当前近战接触线段位于角色坐标上方 1 米：目标满足近战包络时，查询到对方同高度位置为止；否则查询面前 2.2 米，支持没有近处敌人的撞墙挥击。低矮障碍不与线段相交时不反弹；目标后方的墙不抢先于目标命中。这是**真实场景几何上的近战线段检测**，不是逐帧刀刃骨骼扫掠，也不包含独立动态物体。

查询须属于当前实例、未过期且采样请求不早于本次出招。缺失场景、查询未就绪或非法命中数据不按“无遮挡”处理，也不虚构地形反馈。

实际命中地形时，取消这一刀及缓存动作，立即播放四方向反弹状态（上 `466`、右 `468`、下 `467`、左 `469`），以本方向收招窗口结束反馈；电脑同时停止移动和待触发的攻击松键。此次接触不触发对方格挡、受击或扣血。`HIT_POINT_NOTIFY` 使用场景目标 `target_mid=0`、实际命中点／方向／法线和材质，并设置 `ignore_hurt=1`；原客户端按武器的 `scene` 音效事件播放撞击反馈。

材质编号为 `0 water`、`1 rock`、`2 sand`、`3 metal`、`4 wood`、`5 grass`、`6 desert`、`7 snow`。材质取自命中形状的原始用户数据；未知值保留为 `-1`，交由客户端原有回退处理，不统一伪装成石头或水。

左右攻防使用相对位置与朝向近似判定，不计算逐帧武器轨迹：攻击满足上述近战范围且未被地形挡住时，防守者处于未松键的左／右招架保持阶段，并且攻击者位于防守正面左右各 60° 内，即可格挡。左、右格挡均可挡左、右攻击，不再固定方向配对；侧后方攻击不被挡住。上下仍只允许上挡上、下挡下，冲刺仍由下格挡处理。

电脑沿用面对面时选择镜像左右招架的动作偏好，但该偏好不限制玩家或电脑的格挡判定。成功时取消攻击窗口、双方原动作阶段及已缓存动作，按各自实际攻防方向下发原资源中的反馈：

| 攻击者方向 | 防守者方向 | 攻击者被招架 | 防守者招架成功 |
| --- | --- | ---: | ---: |
| 上 | 上 | 240 | 231 |
| 右 | 左／右 | 246 | 左 234／右 232 |
| 下 | 下 | 252 | 233 |
| 左 | 左／右 | 258 | 左 234／右 232 |
| 冲刺（离线配对） | 下 | 443 | 233 |

玩家慢跑、快跑提示与 Shift 冲刺链路及参数见[运行时契约](runtime-contracts.md#慢跑快跑与冲刺攻击)。电脑仅招架冲刺，仍只主动使用四向普通攻击；冲刺被挡或撞地形后的恢复为 350 ms。

反馈使用完整 `STATE_SYNC`，双方互为目标 RID；不再用普通攻击收招或防御松键动作替代。反馈期间不启动新攻击或覆盖动画。防守方反馈持续 200 ms，仍按住防御时回到保持阶段，已松键则回待机；松键不截断成功反馈。攻击者反馈沿用本方向的收招窗口（400–530 ms）后回待机。这些反馈时长是本地约定，不是已恢复的原服硬直公式。

未挡住的攻击打断目标动作，电脑同时停止追击；使用原受击状态 `35`，400 ms 后恢复待机。受击期间不接收新的攻击或招架。伤害、受击时长与命中范围是本地规则，未宣称还原原服伤害公式。

| 消息 | 用途 |
| --- | --- |
| `BATTLE / DATA_UPDATE_NOTIFY`（4 / 11） | 更新隐式本地玩家血量；不用于电脑。 |
| `ATTR / ATTR_UPDATE`（15 / 1） | 用显式实体 RID 更新电脑血量；`attr_type=1`，恢复延迟和速度为 0。 |
| `BATTLE / HIT_POINT_NOTIFY`（4 / 27） | 通知命中点与双方身份；地形目标为 0，传递实际材质以复用场景音效。 |
| `BATTLE / STATE_SYNC`（4 / 4） | 同步受击、招架反馈及地形反弹，携带序号、时间与目标 RID。 |

命中不会发送 `BATTLE_RESULT`、`DEAD_NOTIFY` 或伪造击杀结算。

## 生命周期与诊断

阵营确认时，分别发送玩家与电脑的 `UPDATE_ACTOR_BASIC_INFO` 和阵营通知，建立战局成员名单。VISION 只负责场景实体，不替代成员导入。确认出战时，电脑与玩家一样发送一次 `DEL/ADD`，避免加载阶段的 VISION 早于场景创建就绪；电脑使用自己的 `IN_SCENE` 状态，不改变玩家身份或准备倒计时。

[bot.py](../src/Business/scripts/bot.py)每 100 ms 决策、50 ms 推进位置，常规重寻路间隔为 500 ms；动作阶段继续使用 [battle.py](../src/Business/scripts/battle.py) 的原武器时长。观测位置明显偏离计划时，从观测位置重新规划，不把实体拉回旧路径。

电脑复用玩家的慢跑／快跑移动状态表：前进、左前、右前分别为 `2/3/9` 与 `10/11/12`；移动轴按路径方向相对模型朝向计算。连续前进计时在常规重寻路时保留，在停车、动作中断、快照失效、到达终点或观测位置纠偏时清零。单次推进最多计入 100 ms；跨越 2 秒阈值的更新按慢跑和快跑各自占用的时间计算距离，定时器延迟不产生瞬移或立即进入快跑。

转向采用最短角度差，速率上限为本地调节值 360°／秒；转向后与路径方向仍相差超过 45° 时原地转身，否则按前进或斜前进播放动画。每次推进最多走完一段路径，下一次更新再处理拐角，避免跨拐角直切。近战前转向完成后才开始反应等待。这里对齐的是步速、起跑节奏和移动状态；电脑仍由 AI 决定路线并通过 MOVE 同步，不接管玩家输入，也不等于复现玩家原生输入控制器的全部行为。

离场取消所有电脑和战斗定时器，断线丢弃会话，新实例重建状态。VISION 刷新保留双方血量及电脑的位置、朝向和动作，不重新出生或回血。状态版本 `5` 接受旧版本 `1/2/3/4`，旧对局不补建电脑或血量状态；血量、受击期限、格挡／地形反馈、动作、路径和前进计时可随热更新保留，缺少前进计时的旧状态从慢跑开始。实时朝向和地形查询需要配套的原生 Runtime，升级后须重启启动器和客户端，而非只热更新脚本。

业务日志只在状态变化时输出 `bot status=...`：

| 状态 | 含义 |
| --- | --- |
| `world-unavailable` | 双实体尚未就绪、快照过期或实例已变。 |
| `navigation-unavailable` / `navigation-invalid` | 资源缺失、读取失败或不符合支持的资源配置。 |
| `outside-mesh` / `no-path` | 当前位姿不在支持的网格上，或没有可通行走廊。 |
| `approach` / `ready` / `attack` / `parry` | 追击、反应等待、攻击、招架。 |
| `turning` | 近战前正在转向目标，尚未开始反应等待。 |
| `observe-threat` / `late-threat` | 正在观察有效攻击威胁，或本次出招已不适合再起格挡。 |
| `counterattack` | 利用对手收招或反弹阶段起手反击。 |
| `contact-unavailable` | 普通攻击的距离、朝向或地形接触条件尚未满足。 |
| `hurt` | 正在受击，暂停电脑决策。 |
| `parried` / `parry-success` | 正在播放被招架／招架成功反馈，暂停电脑决策。 |
| `terrain-rebound` | 攻击撞到地形，正在播放反弹反馈。 |
| `stopped` | 已离场或不再可操作。 |

命中日志为 `combat-hit attacker=... target=... hp=...`；成功招架记录 `combat-parry attacker=... target=... attack=... defence=...`，附双方实际动作意图；地形碰撞记录 `combat-terrain attacker=... material=... point=...`，每刀至多一次。

每次实际选招记录 `bot-decision reason=attack/parry/counterattack intent=...`，便于区分普通攻击、格挡和反击；等待期间不逐帧输出选招日志。

每次未命中挥击仅记录一次 `combat-miss attacker=... reason=...`，不逐帧刷日志。原因包括 `range`（距离）、`height`（高度差）、`facing`（朝向，附距离和夹角）、`heading-unavailable`、`world-unavailable`、`terrain-unavailable`（场景查询缺失、无效或早于出招）、`interrupted`（动作被打断）。地形接触不是静默的 `obstructed` 空刀。

真实客户端验收：

1. 用新产品包进入一局人机对战，确认战绩面板敌方人数为 1、名字为“电脑玩家”；确认出战后，出生点附近应有一个电脑角色，准备阶段不移动、不攻击。
2. 开局后靠近观察电脑转向和攻击；主动命中电脑应有受击动作，受到电脑攻击时玩家血条应减少。有效近战范围内，分别用左、右格挡防御电脑的左、右攻击，四种组合在防守正面各 60° 内均应成功；反向攻防使用同一规则。转到防守侧后方应能命中，上下仍只允许上挡上、下挡下。成功招架不扣血，立即中断攻击，并按双方实际动作方向播放反馈。
3. 拉开距离，沿平地、墙边、拐角和坡道移动，观察追击、绕行、高度与停止位置；离开可达区域时应停下，而不是穿墙直追。在足够长的直线上比较双方起步与连续前进 2 秒后的速度、动画；电脑停车、攻防或受击后应重新慢跑起步。急转弯应先转身再前进，小角度转弯保持步速并匹配斜前进动画，不瞬间掉头或横滑。
4. 验证玩家 WASD、镜头、跳跃和蹲伏仍正常，电脑不接管玩家输入。
5. 连续攻击至零血量，确认不变负数、不死亡、不结算；一挥多帧接触只扣一次血。离场再开一局，血量恢复为 100，旧动作与定时器不残留。
6. 原地转身和围绕电脑移动后再攻击，确认实际朝向用于命中。发生穿模无反馈时，记录对应的 `combat-miss`、`combat-parry` 或 `combat-hit`，以及距离、动作方向和是否靠墙。
7. 分别对木栅栏、石墙挥击，检查反弹方向、攻击中止和材质撞击音效；双方隔障碍时不扣血。再在低台阶／坡边、无遮挡高差处攻击，确认只在近战线段实际碰撞时反弹；检查目标身后有墙、附近没有敌人和电脑撞墙的情况。
8. 分别面对、背对电脑挥刀，观察是否仅对有效威胁起格挡。电脑空闲时让玩家进入收招，检查 `counterattack` 选招日志；持续交战时攻击不再固定四方向轮换，也不连续重复同一方向。分别保持上、下、左、右格挡，观察其攻击选择，确认左右格挡对两种横向攻击的覆盖规则未变。

已人工确认寻路、电脑主动攻击、双向伤害和防御动作。移动步速与动画对齐、行为树策略、格挡反馈、地形反弹音画及近战线段的实际手感需按上述步骤复验。
