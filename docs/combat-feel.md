# 战斗手感

手感取决于四件事：本地操作无延迟、命中反馈与画面同步、对手动作可信、判定公平。本项目沿用成熟动作游戏的做法，并受限于原版客户端的结构。

## 原则与做法

| 原则 | 业界做法 | 本项目 |
| --- | --- | --- |
| 本地操作零延迟 | 本地角色由客户端立即响应，服务端只校验 | 原版客户端自行移动，服务端校验速度预算，不接管 |
| 命中与画面同步 | 伤害、音效、特效绑定到动画的有效帧，而不是请求到达的时刻 | 每个命中结果携带攻击者刀刃接触的时刻，客户端等画面播到该时刻再呈现，见下文“呈现时钟”；PVE 与 PVP 共用 |
| 防止连击锁死 | 受击硬直之后给予短暂的抗打断（韧性／霸体） | 怪物硬直结束后 800 ms 内不再进入新的硬直 |
| 攻击有节奏 | 同一目标同时只有少数敌人出手（攻击令牌），其余绕行 | 同一目标的怪物起手至少间隔 700 ms，其余沿目标侧移 |
| 不卡死 | 卡住检测、绕行与放弃目标 | 见 [PVE](../game-server/docs/pve.md) 的怪物行为 |
| 判定公平 | 延迟补偿：按事件发生时的画面回溯，而不是处理时的状态 | 服务端保存姿态历史，按接触发生时间回溯裁决 |

## 呈现时钟

客户端把远端演员（其他玩家与怪物）的动作和位置延迟 100–180 ms 回放（`online_playback`），以便插值。命中裁决到达客户端的时间却只取决于网络，所以在延迟较低时，伤害、出血和受击会早于画面上的刀光。

裁决与呈现分开处理：

- **裁决**（Rust）：真人攻击按攻击者上报的接触时刻回溯，规则不变。怪物攻击由服务端合成，接触窗口整体后移 `PRESENTATION_DELAY_MS`，按玩家看到刀落下那一刻的站位判定，看见自己躲开就不会被判中。该常量与 `online_playback.BASE_DELAY_MS` 必须相等，由测试保证。
- **呈现**（Python，`online_presentation`）：Rust 为每个接触结果附带 `causeAt`，为它引起的受击、弹刀、反弹与死亡动作附带 `cause: {actorId, at}`，即攻击者的刀在其动作时间线上碰到目标的时刻；怪物的这个时刻是裁决时刻减去 `PRESENTATION_DELAY_MS`。客户端在攻击者的回放时钟播到该时刻时，才呈现命中点、扣血、受击和击杀。

规则只看攻击者在本机画面上的时钟，PVE 与 PVP 共用一条路径：

| 攻击者 | 何时呈现 |
| --- | --- |
| 本机玩家 | 立即。自己的刀没有回放延迟 |
| 远端玩家或怪物 | 该攻击者的回放播到 `causeAt` 时 |
| 无回放样本、出生或死亡中、回放停滞 | 立即，或最迟到达后 `MAX_DELAY_MS`（180 ms） |

接触结果携带整张生命表，必须按序应用；动作按角色保持序号。所以一条被挂起的结果会挡住同一通道的后续结果，最多 180 ms。断线恢复以服务端现状为准，丢弃仍挂起的结果。

## 本机命中反馈

自己的刀砍中怪物时，原生刀刃接触一上报，客户端就立即播放命中点特效（出血与打击），不等裁决往返（`online_combat.predict`）。怪物从不格挡，这次接触不会被改判为弹刀。裁决回来后只补伤害数字、血量、受击与击杀，不重复播放特效。打真人时仍以裁决为准，原因见“尚未实现”。

## 尚未实现

- **命中停顿**：命中瞬间双方动画短暂停止，是强烈的打击感来源。需要能暂停原生动画的钩子，目前没有。
- **按武器的有效帧**：怪物接触窗口仍是固定值，没有按武器单独配置。
- **按玩家实际延迟裁决的怪物攻击**：怪物裁决只后移固定的 `PRESENTATION_DELAY_MS`。网络抖动使某个客户端的回放延迟超过 100 ms 时，该玩家看到的刀仍比裁决晚。
- **打真人的本地命中反馈**：打中真人对手后，出血要等裁决回来（一个往返）才出现。对手的格挡在他自己的画面上可能已经举起，而本机还没看到，服务端可能把这次接触判为弹刀；先播出血再弹刀的矛盾反馈比晚一个往返更糟，所以不做预测。
