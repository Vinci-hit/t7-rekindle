# 联机同步审查清单

## 目标与当前链路

本清单供代码审查及弱网验收使用。客户端通过 C++ Runtime 采样，由 Python 适配为 WebSocket 消息，Rust 处理房间与战斗，再由接收端 Python 播放远端位置、转换动作消息。位置快照与可靠事件使用两条绑定同一会话的 WSS/TCP 连接。动作和接触附带最近自身位姿检查点，并复用原位姿校验，避免跨通道超车误拒。

位置采样目标为 20 Hz，不等待业务回复；未发送的快照合并为最新值。样本携带发送端 tick、位置、速度、空中标记、动作编号和动作起始 tick。远端播放使用独立缓冲与受限时钟调速，基础插值延迟为 100 ms，并根据到达抖动提高，最大 180 ms。自身位置不应用远端回显。

当前缓冲耗尽时使用有限外推：地面最多 100 ms，空中最多 150 ms，到上限后保持外推终点；反应状态不沿旧速度外推。原生跳跃表现、反应期间位移所有权及恢复交接已接入；实机仍反馈远端跳跃顿挫，不能视为已解决。已移除空中地面驱动，并让受击及恢复绕过位置缓冲，仍需逐帧验收。

## 验收建议

1. 双端分别记录本机原生采样 tick、快照序号、接收时间、缓冲水位、播放 tick、位置和动作阶段。记录中避免票据或个人信息。
2. 覆盖静止跳跃、跑跳、空中攻击、移动中弹刀、受击后恢复、死亡复活和下一局状态清理。
3. 对照本机、局域网及模拟公网条件，观察 RTT 20/100/200 ms、抖动 0/30/80 ms、丢包 0/1/3%。这些是测试条件，不是性能承诺。
4. 自动测试通过后仍需实机录像与测量。当前没有完整弱网、20 人实机或多房间尾延迟验收结果。

## 预测层回归要求

自机动作、场景接触和明确武器接触已加入表现预测；玩家肉体重叠不预播音效，避免权威格挡时同时听到肉声；伤害、受击、弹刀结果和结算仍由 Rust 决定。逐个确认权威动作序号与状态，相同广播不重播，冲突会中止预测。该实现尚未完成公网实机验收，不能视为已经消除打击延迟。

- 检查零时长格挡准备、提前松键、连续变招、冲刺前置条件与武器切换时的预测／权威序列是否一致。
- 当前纠正会取消预测，不重放纠正前未确认的输入；服务端静默忽略的意图也缺少明确的拒绝原因。高抖动下可能回退至等待权威状态，需要实测及后续输入确认协议完善。
- 预测接触仅覆盖本机攻击者；被击方仍等待权威受击，防御只查询已接受的历史，不回滚已经结算的命中。错误预测的短暂火花和音效不能撤销。
- 地面小误差校正、远端跳跃表现、反弹位移交接、传输拆分与有限防御回溯已接入；完整时钟校准、可靠输入重演及弱网实机验收仍未完成。
