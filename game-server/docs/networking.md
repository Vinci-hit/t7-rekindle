# 房间任务与移动协议

## 所有权和队列

路由任务持有连接身份、账号占用、房间地址与只读目录快照。每个房间由独立 Tokio 任务持有 `RoomState`、成员连接、动作与位置历史和待裁决接触；房间任务之间不共享战斗可变状态。

房间每 25ms 推进一次，动作仍按理论截止时间补齐阶段。位置发布保持 50ms。接触截止检查独立于房间 tick，提前就绪时立即裁决；提高 tick 不改变攻击时长、裁决宽限或插值策略。Tokio 可以跨线程调度房间任务，但不承诺每房间独占核心。

- 路由命令队列最多 1024 条，房间命令队列最多 256 条。可靠命令不丢弃后继续游戏；房间队列满时关闭对应连接并排队清理，其他房间继续运行。
- 加入、离开通过异步所有权交接完成。只暂停该连接，最多缓冲 64 条后续命令，按原顺序恢复；保留身份、时钟校准、重放缓存及移动连接。失败加入返回大厅，空房任务退出。离开时尚未完成的接触回复为拒绝，不把未确认请求遗留到下一房间。
- 上行移动每连接只有一个最新值槽位，收包唤醒当前所属房间；覆盖旧样本不经过全局命令队列。移动中的战斗序号仍是跨连接屏障，不能当作战斗输入已经到齐。
- 下行移动每连接、每角色保留一个最新待发送快照，按事件序号取出。慢发送期间同一角色的旧位置被替换，阶段变化清理未发送的旧场景快照。可靠事件仍使用有界 FIFO。

路由入口、操作系统调度、TCP 重传和客户端处理仍可能排队。`command queue delay` 记录可靠请求从入队到房间处理的时间；应在公网与负载测试中分别观察 p50/p95，不能把任务拆分视为零延迟保证。

## WebSocket 格式

`/ws` 使用 UTF-8 JSON，单请求最多 4096 字节。`/ws/motion` 仅接受下列固定二进制帧，不接受 JSON；它绑定主连接的会话能力，不能修改身份或携带攻击命令。服务端与原生网关必须一起升级。

数值均为小端；浮点为 IEEE 754 f32。UUID 为标准顺序的 16 字节，不使用 Windows GUID 的混合端序。所有字段逐项读取，禁止直接把未对齐字节转成结构体引用。

上行 `T7M1` 共 **119 字节**：

| 偏移 | 字段 | 格式 |
| --- | --- | --- |
| 0 | 标识 | `T7M1`，4 字节 |
| 4 | 移动通道请求序号 | u64，正数，独立于可靠连接 |
| 12 | 对局 UUID | 16 字节 |
| 28 | 位置输入序号 | u32，正数 |
| 32 | 位姿 | 下表，47 字节 |
| 79 | 时钟 epoch | UUID，16 字节 |
| 95 | 已发战斗序号高水位 | u64 |
| 103 | 原始采样时间 | u64，客户端单调毫秒 |
| 111 | 网关处理时间 | u64，同一客户端时钟 |

下行 `T7S1` 共 **107 字节**：

| 偏移 | 字段 | 格式 |
| --- | --- | --- |
| 0 | 标识 | `T7S1`，4 字节 |
| 4 | 房间 UUID | 16 字节 |
| 20 | 对局 UUID | 16 字节 |
| 36 | 房间角色 ID | u32 |
| 40 | 位置事件序号 | u64 |
| 48 | 位置输入序号 | u32 |
| 52 | 服务端时间 | u64，服务端单调毫秒 |
| 60 | 位姿 | 下表，47 字节 |

位姿相对偏移：

| 偏移 | 字段 | 格式 |
| --- | --- | --- |
| 0 | 位置 x/y/z | f32 × 3 |
| 12 | 朝向 | i16，−180..180 度 |
| 14 | 前后 / 左右输入 | i8 × 2，−1..1 |
| 16 | 标志 | u8 |
| 17 | 发送端 tick | u64 |
| 25 | 动作起始 tick | u64 |
| 33 | 动作状态 ID | u16 |
| 35 | 速度 x/y/z | f32 × 3 |

标志 bit 0 为奔跑，bit 1 为包含运动帧，bit 2 为空中，bit 3 为跳跃，bit 4 为包含时间线；其余位必须为零。下行禁止 bit 4。未包含的运动帧或时间线字段必须全零。起始 tick 不晚于当前 tick，跳跃必须同时为空中，数值须有限并通过现有位置/速度规则。错误长度、标识和结构会关闭移动及所属主连接。

合并允许位置输入序号及事件序号跳号，客户端只应用比当前更新的样本。主连接事件和移动快照有独立序号，不等待位置确认。该编码减少网络体积和 JSON 工作量，仍有复制、UUID 转换和业务验证成本；目前客户端位置采样仍经过 Python 适配层。
