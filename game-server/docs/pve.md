# 协作 PVE

Rust 拥有房间、波次、怪物身份、目标选择、动作和伤害。客户端适配器负责原生关卡初始化、怪物显示、姿态和战斗消息转换。服务端提供波次闭环，原生适配器提供单关卡试玩入口与怪物消息转换；实际地图和模型表现仍需实机验收。

## 配置

默认不启用 PVE。启动时添加 `--pve-scenarios scenarios.json`。配置来自服务端，客户端只提交 `scenarioId`，不能指定怪物资源、出生点、血量或波次。

以下编号和坐标均为协议示例，需要替换为客户端可用的资源与出生点；此文件不提供原版关卡配置。

```json
{
  "scenarios": [{
    "scenarioId": 1,
    "mapId": 7001,
    "instanceId": 8001,
    "mapResourceId": 9001,
    "playerSpawns": [[0, 0, 0]],
    "monsterSpawns": [[8, 0, 0], [0, 8, 0]],
    "monster": {
      "resourceId": 10001,
      "heroId": 10001,
      "weaponId": 10002,
      "health": 100,
      "speed": 2
    },
    "waves": [2, 4, 6],
    "intermissionMs": 3000,
    "spawnSchedule": {"batchSize": 2, "intervalMs": 1000}
  }]
}
```

`mapId` 是大厅场景编号，`instanceId` 是关卡编号，`mapResourceId` 是底层地图资源编号。不得互换。原生进房与实例初始化发送 `instanceId`，客户端再通过关卡表解析底层地图；不能在这两种报文中填写 `mapResourceId`。每份目录最多 32 个场景、4 MiB，每场最多 128 波，每波 64 只怪物。坐标采用客户端的世界坐标，Z 为高度。速度为世界单位/秒，限制为 0.1–10；血量为 1–65535。配置非法则启动失败。

`spawnSchedule` 可选。省略时一次生成整波；设置后，每波按 `batchSize` 分批生成，间隔为 `intervalMs`（100–60000 毫秒）。每批 1–64 只，最后一批按剩余数量生成，出生点跨批次依序循环。一次更新最多生成一批，延迟更新不会补发积压批次；间隔从实际出生时间计算。只有计划数量全部生成、怪物全部死亡并移除后，才进入下一波或胜利；两批之间暂时没有活怪不算清场。该配置描述服务端调度规则，不代表原版关卡触发脚本。

`birth` 可在场景或单处 `encounters` 中选择原生非战斗出生动作，遭遇配置优先。例如 `"birth": "emerge1"`。可选 `emerge1`、`emerge2`、`emerge3`（3167 毫秒）、`vault1`（1800 毫秒）、`vault2`（3433 毫秒）。需要怪物的客户端资源支持对应动作；这些名称不表示已恢复原版刷怪组与爬墙路线的绑定。

出生快照含 `birth: {animation, startedAtMs, endsAtMs}`。服务端暂停追击与主动攻击，适配器依序发送非战斗模式与出生状态通知，期间不发送普通行走指令。非致命伤害照常扣血，但不打断出生动画；适配器消费受击与恢复序号，不切换原生出生图，也不通过命中反馈触发受击。结束后快照移除 `birth`，适配器退出非战斗模式，再恢复行走。死亡清理出生呈现；重复生命周期更新不会重播。出生动画不能与 `spawnEntrances` 同时驱动位置。客户端骨骼、特效和模型切换仍需实机验收。

`spawnEntrances` 可为每个出生点配置一条自建入场轨迹；列表长度必须与 `monsterSpawns` 相同，省略或空列表时直接出生。出生点表示落点，`startOffset` 表示起点相对落点的偏移，`arcHeight` 表示额外弧线高度，`durationMs` 表示入场时长。例如两个出生点可分别使用：

```json
"spawnEntrances": [
  {"startOffset": [0, -4, 2], "arcHeight": 1, "durationMs": 1800},
  {"startOffset": [0, 4, 2], "arcHeight": 1, "durationMs": 1800}
]
```

入场由 Rust 独占位置控制，完成后再切换追击；入场期间不主动攻击，死亡后停止推进轨迹。轨迹每次最多推进一个 AI 步长，延迟更新不跳到终点。偏移每轴不超过 20、弧高 0–10、时长 500–10000 毫秒，并要求轨迹速度上界不超过 20 世界单位/秒。该功能只复制位置，不触发原版爬墙动画，不检测墙体或采样地面高度，落点应在地图内验收。

## 接近触发与地面行走

`encounters` 可选，数量必须与 `waves` 相同；每项描述一处有限遭遇，`waves` 的对应项是该处怪物总数。省略时沿用定时波次。示例：

```json
"encounters": [
  {"triggerPosition": [10, 0, 0], "triggerRadius": 12, "monsterSpawns": [[14, 0, 0]]},
  {"triggerPosition": [40, 0, 0], "triggerRadius": 12, "monsterSpawns": [[44, 0, 0]]}
]
```

只有存活玩家的有效姿态进入半径且高度差不超过 3 时才触发。一次运行一处遭遇，优先选择距离玩家最近的未访问区域；清场后重新等待接近，不重复刷已清区域。全部区域清完才胜利。每处可通过 `monster` 覆盖场景的怪物类型、武器、血量和速度。接近触发不能与 `spawnEntrances` 同时配置。

`encounterOrder` 默认为 `nearest`，选择最近的未访问遭遇。线性关卡可设为 `sequential`，严格按 `encounters` 数组顺序推进：未来区域即使已有玩家进入也不会提前激活；当前遭遇的全部计划批次生成、怪物死亡且移除后，才允许触发下一处。等待仍受接近、高度、导航连通和波间间隔约束。

`proximity` 用于沿路触发的遭遇：玩家接近未访问区域便生成该区域的怪物，不要求先杀完前一区域的怪物。每处计划怪物在容量允许时一次生成，不使用 `spawnSchedule` 的分批间隔；全场仍最多保留 64 只怪物，容量不足时待释放后继续生成。护送、收集和守护目标仍须完成才推进目标流程；全部区域已触发且剩余怪物全部清理后才胜利。`proximity` 必须配置 `encounters`。

出场动画不提供无敌：命中按当前武器的接触窗口验证，受击中断钻出动作。原生战斗动作播放期间，姿态更新只同步位置和朝向，不通过移动待机状态重置攻击或受击动画。


每处遭遇可配置 `objective: {"approach": "前往入口", "active": "清除入口敌人"}`，文本各为 1–128 个字符，不含控制字符。快照可携带 `objective: {encounter, text, targetPosition, active}`：`encounter` 为从 1 起的配置下标；顺序关卡等待时显示下一处的 approach，激活时切换 active。胜败后省略目标。初始视图与重连视图从当前状态生成，不依赖客户端收到过先前的切换事件。目标可额外配置 `approachTaskId`、`activeTaskId`，快照选择对应的 `taskId`。适配器通过原生 command 11 的任务提示更新资源表文字与计数，同一任务和计数不重复发送，结束时隐藏。任务编号须存在于目标客户端资源中；箭头与字幕尚未接入，任务显示仍需实机验收。任务顺序、坐标和怪物数量由配置提供，不按参考视频的播放时间触发。

## 任务目标

每处遭遇可配置 `goal`，省略时为 `{"type":"clear"}`。任务由房间状态推进，客户端不能提交完成标志；仅使用存活且姿态未过期的玩家。目标满足、计划怪物全部生成且尸体移除后，才进入下一处。

| type | 配置 | 完成条件 |
| --- | --- | --- |
| `clear` | 无 | 清除计划怪物 |
| `reach` | `position`、`radius` | 存活玩家到达目标三维范围 |
| `collect` | `points`、`radius` | 队伍接近全部收集点，每点仅记一次 |
| `escort` | `path`、`radius`、`speed` | 玩家在附近时推进路线，无人靠近则暂停 |
| `defend` | `position`、`radius`、`durationMs`、`health` | 玩家在附近累计守护时间，且目标未被怪物摧毁 |

非 `clear` 目标的对应 `waves` 可为 0，表示不附带刷怪；清怪目标必须至少一只。`collect` 为接近收集规则，不等同原版交互键拾取。护送与守护每次最多推进 100 ms，服务端卡顿不补发整段位移或守护时间。怪物在玩家和守护点之间选择最近的可达目标，使用攻击动作的有效接触窗口扣除守护点血量；目标归零以 `pve-objective-destroyed` 结算失败，区别于玩家全灭。

例如收集目标：

```json
"goal": {"type": "collect", "points": [[10, 0, 0], [14, 2, 0]], "radius": 1.5}
```

有导航时，目标点必须位于网格，护送路线各段必须连通；启动时沿合法面走廊展开路线，拒绝穿越不连通区域。`goal` 快照携带类型、计数、目标位置、完成标志，守护额外携带当前与最大血量；重连读取当前进度，不重跑进入动作。

每处遭遇还可配置 `objects`：每项含 `resourceId`、`position`、`binding`。绑定类型为 `static`、`escort`、`defend`，或 `{"type":"collect","index":0}`；类型须与该处任务一致，收集下标从 0 起。激活时创建原生动态物件，护送位置与守护血量由任务驱动，收集后移除对应物件，阶段结束时移除该处物件。物件使用独立身份与实例区间，不占玩家或怪物槽位。生命周期、位置和血量发送原生协议；模型、动画和界面表现仍需实机验收。首领技能与完整关卡配置需独立提供。

`monsterPool` 可为遭遇提供最多 32 种怪物，按出生序号循环选择，不能与单个 `monster` 覆盖项同时填写。此处是显式配置的确定性选择，不推断原版随机权重。

`navigation` 可提供 `polygons` 与 `links`：前者为凸多边形的逆时针世界坐标顶点，后者为每个面的相邻面下标数组。邻接必须双向且共享可行走边，不能凭距离连接隔墙区域。最多 16384 个面，每面 3–32 个顶点；非法几何在启动时拒绝。地面出生点必须落在网格内，同一遭遇的出生点必须与触发点连通。

配置导航后，Rust 使用空间索引查询地面、按邻接计算路径并缓存追击路线，每步重新采样高度；不可达时停止，每个 AI 步重新检查目标；恢复可达或更换目标时清除旧路径并立即重新寻路，不等待路径缓存到期。不穿墙或向目标瞬移。僵尸只追击同一行走区域内的玩家。此路径规划不处理跳跃、攀爬、动态障碍或人群避让。

客户端移动适配发送原生走路／停止状态、方向和配置速度，同时更新位置；攻击、受击和死亡继续通过战斗动作通道驱动。单纯位置校正不具备行走动画语义。死亡时先停止移动，避免尸体继续沿旧指令滑动。模型动画仍需在目标客户端实机验收。

## 协议与流程

通过现有游客票据或本机开发身份建立 WebSocket 后，发送：

```json
{
  "protocolVersion": 1,
  "requestId": "2",
  "command": {
    "type": "createPveRoom",
    "payload": {"name": "Cooperative", "scenarioId": 1}
  }
}
```

加入、准备、开局、加载和退出沿用现有房间命令。PVE 最多四名玩家，实际容量还受 `--room-capacity` 限制；玩家均为阵营 1，怪物为阵营 2。房主可单人开始，其他成员必须准备。所有真实成员加载后统一倒计时。

`Room`、`RoomChanged`、房间列表和 `ClientView` 包含 `mode: "pve"`。房间与视图的 `pve` 字段包含关卡资源、玩家出生点、波次和怪物快照。适配器按成员顺序选择玩家出生点，点不足时循环使用。

`PveChanged.payload.update` 包含房间、对局、递增事件序号、服务端时间和完整 `snapshot`。怪物出生、血量变化、死亡、移除及波次切换通过此事件可靠发送；移动与动作继续使用 `PoseChanged`、`ActionChanged`，命中与血量继续使用 `CombatChanged`。怪物身份位于独立高位区间，适配器保持其 RID，动态更新映射，并将移动与动作消息的 16 位实例号分配到 1024 起的独立区间；不得将怪物挤入玩家槽位。每局重新分配，身份必须与 `matchId` 一起解释。

怪物生命周期快照先于同轮动作和移动事件发送。适配器必须先创建已出现的怪物，忽略已移除对象的残留更新。等待和加载阶段无怪物；进入 Running 后按定时波次或接近触发规则创建怪物。玩家攻击怪物沿用 `ContactInput`，仍校验动作窗口、距离、朝向和重复命中。PVE 玩家打怪使用适配器采样到的本机刀刃端点，对简化直立身体体积做帧间扫掠，保留接触高度供头、身、腿伤害和原生提示使用。每刀每目标只结算一次，允许横扫多个目标；没有采样接触时不再由服务端距离补判。该体积尚不跟随怪物骨骼，不等同于原生怪物逐骨骼碰撞。怪物攻击由 Rust 生成接触报告，经过同一伤害与格挡规则；客户端没有 AI 输入权限。

怪物死亡时适配器立即移除客户端实体及其碰撞代理，迟到的动作和位移不再呈现；服务端保留一秒生命周期记录后移除。顺序波次全部移除后进入波间等待，接近触发模式允许旧区怪物存活时激活新区。接近触发只检查配置半径和三米高度差，不要求触发点与玩家属于同一 AI 导航连通区；导航连通性仍用于怪物追踪。最后一波结束判玩家胜利；全员死亡判失败，存活队友仍在时可使用原有复活流程。超时判失败。结算只保留玩家计分，展示完成后回到等待阶段，清空怪物、波次与输入状态。

## 运行约束

AI 每 100 ms 更新一次，姿态沿用 20 Hz 发送节拍。每只怪物只选择最近的存活且姿态有效的玩家；延迟 tick 最多推进 100 ms 的移动量，不补发整轮攻击。未配置导航时沿用平面直线追踪；配置后沿静态网格追击并采样高度。尚无 Boss 技能、机关目标、商店或奖励存档。复杂地图必须补充寻路与怪物动作配置后验收；这套波次规则不代表原版关卡脚本已还原。

验证包含配置限制、四人同队、加载超时、怪物攻击与玩家格挡、玩家击杀与去重、波次和全灭、结算复位、房间隔离，以及真实 WebSocket 生命周期与消息顺序。尚无原生客户端 PVE 实测或多房间压力测试。

### 怪物近战兜底规则

尚未绑定原生怪物刀刃轨迹时，怪物近战使用保守范围判定：距离不超过 1.1 米、高差不超过 1 米、正面 120 度，且仅在出刀阶段 360–540 毫秒内尝试一次命中。出刀锁定目标，后续目标切换不能转移这次命中。同一目标的怪物起手至少间隔 700 毫秒；普通怪物基础伤害为 8，不计算相对速度增伤。守护对象每次受击同样扣除 8 点生命。

这不是刀刃扫掠碰撞，也不代表已还原各类怪物武器参数；不同武器的精确距离与命中帧仍需原始资源支持。
