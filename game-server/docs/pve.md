# 协作 PVE

Rust 拥有房间、波次、怪物身份、目标选择、动作和伤害。客户端适配器负责原生关卡初始化、怪物显示、姿态和战斗消息转换。服务端提供波次闭环，原生适配器提供单关卡试玩入口与怪物消息转换；实际地图和模型表现仍需实机验收。

## 配置

默认不启用 PVE。启动时添加 `--pve-scenarios scenarios.json`。配置来自服务端，客户端只提交 `scenarioId`，不能指定怪物资源、出生点、血量或波次。

以下编号和坐标均为协议示例，需要替换为客户端可用的资源与出生点；此文件不提供原版关卡配置。

```json
{
  "scenarios": [{
    "scenarioId": 1,
    "mapId": 7001,
    "instanceId": 8001,
    "mapResourceId": 9001,
    "playerSpawns": [[0, 0, 0]],
    "monsterSpawns": [[8, 0, 0], [0, 8, 0]],
    "monster": {
      "resourceId": 10001,
      "heroId": 10001,
      "weaponId": 10002,
      "health": 100,
      "speed": 2
    },
    "waves": [2, 4, 6],
    "intermissionMs": 3000
  }]
}
```

`mapId` 是大厅场景编号，`instanceId` 是关卡编号，`mapResourceId` 是底层地图资源编号。不得互换。原生进房与实例初始化发送 `instanceId`，客户端再通过关卡表解析底层地图；不能在这两种报文中填写 `mapResourceId`。每份目录最多 32 个场景、128 KiB，每场最多 32 波，每波 64 只怪物。坐标采用客户端的世界坐标，Z 为高度。速度为世界单位/秒，限制为 0.1–10；血量为 1–65535。配置非法则启动失败。

## 协议与流程

通过现有游客票据或本机开发身份建立 WebSocket 后，发送：

```json
{
  "protocolVersion": 1,
  "requestId": "2",
  "command": {
    "type": "createPveRoom",
    "payload": {"name": "Cooperative", "scenarioId": 1}
  }
}
```

加入、准备、开局、加载和退出沿用现有房间命令。PVE 最多四名玩家，实际容量还受 `--room-capacity` 限制；玩家均为阵营 1，怪物为阵营 2。房主可单人开始，其他成员必须准备。所有真实成员加载后统一倒计时。

`Room`、`RoomChanged`、房间列表和 `ClientView` 包含 `mode: "pve"`。房间与视图的 `pve` 字段包含关卡资源、玩家出生点、波次和怪物快照。适配器按成员顺序选择玩家出生点，点不足时循环使用。

`PveChanged.payload.update` 包含房间、对局、递增事件序号、服务端时间和完整 `snapshot`。怪物出生、血量变化、死亡、移除及波次切换通过此事件可靠发送；移动与动作继续使用 `PoseChanged`、`ActionChanged`，命中与血量继续使用 `CombatChanged`。怪物身份位于独立高位区间，适配器保持其 RID，动态更新映射，并将移动与动作消息的 16 位实例号分配到 1024 起的独立区间；不得将怪物挤入玩家槽位。每局重新分配，身份必须与 `matchId` 一起解释。

怪物生命周期快照先于同轮动作和移动事件发送。适配器必须先创建已出现的怪物，忽略已移除对象的残留更新。等待和加载阶段无怪物；进入 Running 后创建第一波。玩家攻击怪物沿用 `ContactInput`，仍校验动作窗口、距离、朝向和重复命中。PVE 玩家打怪暂用 Rust 的距离、朝向及动作窗口生成接触，尚无精确怪物刀刃采样。怪物攻击由 Rust 生成接触报告，经过同一伤害与格挡规则；客户端没有 AI 输入权限。

怪物死亡后保留一秒供死亡表现，随后移除；全部移除后进入波间等待。最后一波结束判玩家胜利；全员死亡判失败，存活队友仍在时可使用原有复活流程。超时判失败。结算只保留玩家计分，展示完成后回到等待阶段，清空怪物、波次与输入状态。

## 运行约束

AI 每 100 ms 更新一次，姿态沿用 20 Hz 发送节拍。每只怪物只选择最近的存活且姿态有效的玩家；延迟 tick 最多推进 100 ms 的移动量，不补发整轮攻击。暂用直线追踪和现有近战动作规则，没有障碍绕行、地形高度采样、Boss 技能、机关目标、商店或奖励存档。复杂地图必须补充寻路与怪物动作配置后验收；这套波次规则不代表原版关卡脚本已还原。

验证包含配置限制、四人同队、加载超时、怪物攻击与玩家格挡、玩家击杀与去重、波次和全灭、结算复位、房间隔离，以及真实 WebSocket 生命周期与消息顺序。尚无原生客户端 PVE 实测或多房间压力测试。
