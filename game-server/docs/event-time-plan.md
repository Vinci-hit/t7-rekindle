# 战斗事件时间与裁决

目标：统一输入、刀身接触和反馈的时间模型，在有界网络延迟内只提交一次结果。服务端保留最终伤害与状态权威；格挡采用接触时刻的方向与朝向规则。

## 实施状态

- 已实现：接触帧时间诊断；客户端接触结果音画只由服务端触发。
- 已接入：`adjudication::InputWatermark`，验证连续战斗序号、移动通道缺口和提前裁决条件。旧接触帧只补齐序号，不推进输入时间水位；校准 epoch 更换时清空水位。
- 已接入诊断链路：连接级随机 epoch/nonce 校准、20 秒最小往返样本窗口、偏移缓调和不确定区间；动作、接触、校准回传共享连续战斗序号，移动通道携带其高水位。
- 已接入：宿主入队时间与业务处理时间；原生接触帧时间保持原值。动作输入暂用宿主收包时刻，并以 `gatewayInput` 明确标识，尚不是原生按键帧时间。
- 已接入：运行阶段每 50ms 尝试发送 `combatHeartbeat`，与动作、接触共用可靠通道和连续序号，返回 `pong`。最多保留两条未确认心跳，总待发请求达到四条时暂停心跳，为操作留出容量；不发送移动快照或改写角色状态。
- 待实现：原生按键帧时间、已应用快照与事件确认、原生网关实际发包时刻。当前动作时间来自宿主收包，水位也只证明宿主已处理的输入顺序，不证明游戏线程中尚未送出的按键。
- 已接入：服务端动作事件与历史携带 `actionId`，取触发该招的 `inputSeq`，作用域为角色与本局；预输入保留原身份，受击等服务端反应为 null。客户端按动作身份与阶段确认预测，允许服务端跳过本地预测的待机阶段；接触报告通过原生展示序号映射到 `actionId`，服务端按 `actionId` 与阶段查找动作并去重。真实原生网关单人接触流程已通过。
- 已接入：校准后的动作起点用于阶段计时，但能否执行仍由收到输入时的当前状态决定；起点不能跨过已经提交的反应或阶段边界。网络接触报告迟到最多 100ms，独立于动作和位姿历史保留深度；服务端自行等待的时间不消耗报告迟到预算。
- 待实现：授权起点的显式差值确认、接触 ID。本地预测可能先进入待机而服务器直接衔接下一招，不能以两端状态序号相同作为唯一确认依据。
- 已接入：每连接最多 32 条待裁决接触；按已入队接触的事件时间排序，同一局后续接触不越过尚未就绪的前序接触。裁决完成后才回复 `contactAccepted` 并广播一次结果；等待期间不扣血、不播放结果反馈，重复请求复用待定项或最终回复。
- 已接入：历史阶段同时记录生效时间和服务端处理输入的时间。晚于接触裁决期限才处理的格挡和松手，不能改变该接触，即使攻击报告到得更晚。历史弹刀不会重新按下已经松开的格挡。
- 待实现：目标快照区间校验、双方刀身证据、连续轨迹与动作相位验证。
- 待实现：结果按渲染时钟呈现、每个接触结果仅播放一次。

## 约束

水位必须严格超过接触时间加固定宽限，且连续战斗前缀覆盖移动通道声明的序号，才能提前裁决。只收到移动消息不能推进战斗水位。截止后关闭裁决，迟到输入不修改已提交结果。等待期限为 `接触时间 + min(近期 RTT p90 / 2 + 25ms, 70ms)`；缺少有效样本时用 70ms，地形与非玩家目标不等待玩家输入。25ms 包含水位安全余量，不是额外格挡时间。水位需严格超过接触时间 15ms 才允许提前结算；实际格挡仍查询接触时刻，不授予晚按格挡。待裁决期间以 5ms 定时检查到期，并在处理输入后检查提前就绪，不依赖 25ms 的房间 tick。所有数值仍须通过实机测量验证。

格挡按历史防御方向、攻击方向及防守者相对方位裁决：正面 ±60° 左右镜像对应，侧面至 ±120° 仅允许来敌所在侧的同向横砍与格挡，后方拒绝；满足规则的身体接触可转为弹刀，不要求武器接触证据。迟到的未来格挡不能改变过去接触。精确刀身轨迹重建不属于当前裁决规则。

收到输入时的当前状态校验不具备任意到达顺序不变性；当前排序只覆盖已经入队的接触，尚未到达的更早报告无法预知；同时致命交换尚未实现。输入处理时间仍包含路由与房间队列延迟；独立房间任务和移动合并见[网络设计](networking.md)。已提交事件构成不可逆边界。不能宣称窗口外迟到或网络非对称时体验相同。

## 验收

虚拟时钟覆盖 RTT 10/100/200ms 的组合、抖动、200–400ms TCP 停顿、双连接 ±200ms 偏移、重连与重复消息。分别测试宽限边界、连续序号缺口、提交截止、一次反馈、方向与夹角边界、多目标去重及同时致命交换。

统计输入时钟钳制率、报告迟到率、攻击确认 p50/p95、各 RTT 桶格挡成功率与双方刀身证据分歧率。集成测试与实际双客户端体验分别验收，不能以单元测试代替视觉验证。
